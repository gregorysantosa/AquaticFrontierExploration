# Aquatic Frontier Exploration

A ROS 2 Humble workspace for underwater cave-exploration simulation, teleoperation, and autonomous waypoint navigation.

This project uses the Stonefish underwater simulator and the Mini-Alpha AUV to:
- Simulate 3D underwater environments
- Manually teleoperate the vehicle with an Xbox controller
- Run an autonomous waypoint-following node
- Test direct thruster commands for debugging and tuning

---

## Workspace Layout

```bash
ws_sf_ros2/
│
├── src/
│   ├── mini_alpha_bringup/           # Simulation + robot bringup
│   ├── mini_alpha_waypoint_follower/ # Autonomous waypoint navigation node
│   ├── mini_alpha_teleop/            # Xbox controller teleoperation
│   └── ...                           # Additional ROS 2 packages
│
├── build/      # Generated by colcon
├── install/    # Generated by colcon
└── log/        # Generated by ROS 2
````

---

## Setup

In all terminals, run:

```bash
export ROS_DOMAIN_ID=4
unset RMW_IMPLEMENTATION
source /opt/ros/humble/setup.bash

cd ~/ws_sf_ros2
# colcon build --symlink-install # Only if changes do not populate
source install/setup.bash
```

---

## Running the Simulation

### Terminal 1 – Start the Simulator

```bash
ros2 launch mini_alpha_bringup bringup_simulation.launch.py
```

---

## Autonomous Waypoint Following

### Terminal 2 – Waypoint Follower Node

```bash
cd ~/ws_sf_ros2
source install/setup.bash

ros2 run mini_alpha_waypoint_follower waypoint_follower
```

---

## Teleoperation with Xbox Controller

### Terminal 2 – Joystick Setup

```bash
cd ~/ws_sf_ros2
ls /dev/input/js*
sudo chmod a+rw /dev/input/js0
ros2 run joy joy_node --ros-args -p dev:="/dev/input/js0"
```

### Terminal 3 – Teleop Script

```bash
cd ~/ws_sf_ros2
source install/setup.bash
python3 xbox_teleop_mini_alpha64.py
```

---

## Manual Thruster Command Testing

```bash
ros2 topic pub /mini_alpha/stonefish/thruster_command std_msgs/msg/Float64MultiArray \
"{data: [1.0, 1.0, 0.0, 0.0]}" -r 10
```

## Notes and Future Work

- Always source both ROS 2 and your workspace in every new terminal.
- Joystick permissions (`chmod a+rw /dev/input/js0`) may be needed after reboot.
- Somtimes the simulator may not open after starting/stopping multiple times. In this case:
  - Close all terminals
  - Re-initalize them; the same ROS_DOMAIN_ID usually works
  - Start the simulator again
- If the changes in a file do not populate:
  - Rebuild the environment (`colcon build --symlink-install`)
  - Close all terminals
  - Re-initalize them; the same ROS_DOMAIN_ID usually works
  - Start the simulator again
